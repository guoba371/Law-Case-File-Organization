- 版本：v0.2.3，确定首版三类辩护文书、分段初稿 + 修改意见重生成 + 律师逐段确认，以及脱敏参考样本入口；保留原文件路径，已开始开发（模型供应商设置、参考样本入口）。

- 当前阶段：需求整理；已确认本所使用、广泛刑事业务、内部研判、PDF 案卷、检察院阶段集中阅卷，以及原卷/未脱敏 OCR/身份映射留在本所受控环境的边界。具体本地运行方式、单案规模、并发及预算待确认。
- 文档目的：补全功能、收敛首版、定义可验证的安全与质量要求；不是最终技术架构或合规意见。

## 1. 产品定位

定位收敛为：**本所办案团队使用的刑事案卷脱敏与可追溯内部研判工作台**。当前不是面向外部律所销售的商业 SaaS 首发，也不将内部研判误认为当然允许原卷上云。

刑事专用视图、优先级与验收增补见 `criminal-analysis-visualizations.md`。与本稿早期通用功能候选冲突时，以此次用户确认及刑事增补为准；具体新增图表仍是建议，尚未全部确定开发。

本轮范围调整：不再按单一罪名建设独立产品，建议采用“通用刑事研判底稿 + 按案件启用的专题视图”。六类常见案件用于检验通用能力及专题重点，不是六套系统，也不意味着第一版已经支持全部罪名的自动法律判断。

本轮进一步收敛：围绕本所检察院阶段的 PDF 集中阅卷形成首版。需求流程按审查起诉阶段集中整理现有材料组织；具体案件阶段由律师登记，不据此推定全部案卷已经取得或已经起诉。原卷处理边界已确认，但不等于已确定桌面软件、本所服务器或浏览器本地处理的技术形态。

不是“上传文件，让 AI 画一张图”，而是以下可复核闭环：

> 导入材料 → 识别敏感内容 → 人工复核并产生脱敏版本 → 放行指定版本 → 结构化提取 → 校对事件与关系 → 形成可编辑图表 → 带来源导出。

**v0.2.2 定位扩展：从集中阅卷到辩护文书。** 最终目标是辅助辩护律师制作代表委托人向检察院提交的材料，包括法律意见书（不起诉、罪轻、量刑方向）、质证意见、羁押必要性审查申请等，以维护当事人权利并与检察院沟通。系统只基于律师已确认的研判底稿生成论证要点或草稿；文书由律师逐段确认、核验引用并签发，系统不自动提交，也不以检察院名义生成文书。闭环延伸为：

> ……带来源导出 → 选择文书类型 → 基于已确认底稿生成带引用草稿 → 律师逐段采纳与核验法条 → 本所端回填真实身份 → 干净副本检查 → 律师签发对外提交版。

核心价值假设：减少重复整理工作，同时让每项分析都能回到材料核验。需要用试点验证，不把效率提升、识别准确率或客户付费意愿写成已证实事实。

### 1.1 已提出的需求

1. SaaS 产品，服务律所的案卷脱敏与管理场景。
2. 支持案卷脱敏。
3. 将脱敏后的案卷交给 DeepSeek 或 Kimi 等国产大模型进行分析。
4. 提取案件时间轴、事件和人物关系，生成可视化图片。
5. 补充可增加的功能，先形成需求文档。
6. 2026-10-31 用户明确：由自己律所使用，处理刑事案件案卷，成果用于内部研判。
7. 同日补充：诈骗、非法经营、强奸、猥亵、故意伤害、盗窃较常见，基本各类刑事案件都办理；不将业务范围限制为该六类。
8. 同日确认处理边界：按建议将未脱敏原卷、OCR 原文和身份映射留在本所电脑或受控环境，仅将逐版本复核批准的脱敏内容发送至获批服务。此为产品需求决定，不是对实际案卷或任何供应商的外发授权。
9. 同日确认输入与场景：案卷为 PDF，通常在检察院阶段集中阅卷；尚未说明 PDF 中扫描页与可搜索页比例。
10. 同日补充输出偏好：内部传阅和会议查看优先 PDF 或 Word，HTML 可作为交互补充。首版将 PDF 报告和可编辑 DOCX 纳入核心输出，不只交付零散图片；这不改变原卷仅输入 PDF 的范围。
11. 同日明确最终目的：帮助生成法律意见、质证意见，以及为委托的当事人争取权利、与检察院沟通的法律文书材料。
12. 后续确认：首版文书为质证意见、审查起诉阶段法律意见书、羁押必要性审查申请三类；模型生成分段初稿，律师可对段落提修改意见让模型重新生成，最终必须由律师逐段确认；本所暂无模板，系统提供文本输入框和文件上传入口，录入脱敏后的参考样本供生成时参考。

## 2. 用户与权限

| 角色 | 主要任务 | 默认限制 |
| --- | --- | --- |
| 律所管理员 | 管理成员、内部用量、供应商白名单与安全策略 | 不因管理员身份自动获得所有案件正文权限 |
| 案件负责人 | 分配成员、确认分析成果、批准外发 | 仅管理被授权案件，不能查看其他团队保密案件 |
| 承办律师 | 校对事件、关系、证据目录并导出成果 | 外发权限按案件策略授予 |
| 律师助理 | 整理文件、标注敏感内容、提交复核 | 默认不能批准自己的高风险外发 |
| 复核人员 | 检查脱敏、放行指定版本 | 只能复核被分配的案件，不取得全所查看权限 |
| 平台运维 | 维护任务与服务健康 | 不默认读取案件内容；例外访问需限时审批和留痕 |

同一个人在不同案件可有不同角色。是否强制双人复核属于客户策略；高风险案件建议开启，小团队可在明示风险下采用负责人复核并完整记录。外部客户门户不纳入 P0。

## 3. 建议补充的功能及优先级

定义：P0 是首版闭环；P1 在真实试点验证后投入；P2 是明确有需求时才扩展的产品能力。

| 功能 | 用户价值 | 优先级 | 边界 |
| --- | --- | --- | --- |
| 脱敏复核工作台与遗漏检查 | 看清哪些内容被处理，避免直接相信自动识别 | P0 | 可人工补标、撤销误标，未复核不能外发 |
| 同案跨文件稳定代号 | 脱敏后仍可追踪同一人、组织与账户 | P0 | 同名不自动合并，禁止跨案身份关联 |
| 证据目录与材料定位 | 将案卷整理为可引用、可交接的目录 | P0 | 不自动宣布证据真实性或证明力 |
| 事件及关系的证据回链 | 点击任一事件或关系查看对应材料位置 | P0 | 正式成果必须来源有效或明确标为人工备注 |
| 可编辑时间轴与人物/组织关系图 | 校正模型输出后用于讨论和汇报 | P0 | 含未知时间、争议状态、图例和版本 |
| 结果复核队列与版本快照 | 区分机器草稿、律师确认和历史成果 | P0 | 重新分析不能覆盖人工修改 |
| 案件权限、审计和安全导出 | 控制谁能看、谁能发、发出去什么 | P0 | 不做无法兑现的“已下载文件远程销毁” |
| 用量、成本与覆盖范围提示 | 看见处理进度、遗漏页和费用上限 | P0 | 不静默截断整卷、不自动改换供应商 |
| 事实冲突对照表 | 对照不同材料的日期、金额及主体差异 | P1，优先 | 首版仅保留人工争议标注，不自动裁断真伪 |
| 争议焦点—主张—证据矩阵 | 将案件争点与支持/反驳材料对应 | P1，优先 | 律师确认争点与证明目的，AI 只辅助整理 |
| 缺失材料与补证任务清单 | 发现“有主张无材料”等需要追问的事项 | P1 | 区分“本案未上传”与“现实不存在” |
| 限定案件的引用式问答 | 查询卷中记载并回链 | P1 | 资料不足就明确说不足，不编造法规或卷宗事实 |
| 资金流向图与金额对账 | 梳理付款人、收款人、往来款及重复凭证 | P1，按案由 | 币种、退款、重复记录单独处理，不作洗钱等定性 |
| 刑事程序与强制措施泳道 | 区分案件程序、各人的强制措施和相关文书 | P1，按需求 | 日期、期间及适用依据由律师确认，不自动认定超期违法 |
| 内部研判报告与会议材料包 | 汇总阅读摘要、图表、争点、笔录对照、待核查事项与来源目录 | P0：PDF/DOCX | 使用一套内容快照和基础模板；PPT、自定义模板设计器及对外分享后置 |
| 辩护文书辅助（质证意见、审查起诉阶段法律意见书、羁押必要性审查申请） | 把已确认底稿转为带卷页引用的分段初稿，可按修改意见重生成，减少起草重复劳动 | P1 首项，紧接 P0 闭环；首版三类已确认 | 仅用已确认底稿与已确认脱敏的参考样本；法条/案例律师核验；逐段确认；律师签发；不自动提交 |
| 有权限的安全分享空间 | 限时查看、撤销链接、访问记录 | P1 | 撤销访问不等于收回截图和已下载副本 |
| 标准脱敏模板与案件类型模板 | 复用团队规则，减少重复配置 | P1 | 规则升级不自动改写已发布材料 |
| 律所私有化、SSO、专属模型路由 | 服务有特殊部署要求的客户 | P2/独立版本 | 若首批客户将其列为门槛，先重排 MVP，不能假装后补即可 |
| 律所知识库与跨案经验检索 | 复用已经另行授权的工作成果 | P2 | 二次用途审批；默认不跨案检索、不混合身份映射 |
| 音视频转写与多媒体脱敏 | 覆盖录音、庭审、现场材料 | P2 | 声音、面部及背景信息需专门治理 |
| 外部企业关系与法律数据库接入 | 补充经许可的外部资料 | P2 | 来源合法、费用明确，并与本案材料区分 |

**建议优先验证的差异化组合：同案一致脱敏 + 一键证据回链 + 可编辑图谱。** 自动冲突检测和争点证据矩阵是第二阶段优先方向，不能为了堆功能牺牲第一阶段的可靠性。

**刑事修订建议**：优先增加“证据—待证事实关联图”和“同一事项的多次供述/证言对照”。首版从人工确认的关联与对照做起，自动发现矛盾、自动映射犯罪构成要件及全部专用图形不一并进入 P0。详见刑事增补中的 C1—C12。

六类常见案件的专题映射及限制见刑事增补第 5.1—5.3 节。包括资金/经营/财物流转、现场行为与损伤材料、陈述与客观记录核对；同一案件可以组合专题，不按单一指控标签隐藏其他有关材料。涉隐私材料最小展示、人工校对与来源核验属于基础要求，不因专题视图排在后续而延期。

## 4. 首版范围与明确不做

### 4.1 P0 最小业务闭环

建立案件 → 导入材料 → 预检/解析/OCR → 敏感内容识别 → 人工复核 → 生成不可覆盖的脱敏版本 → 指定供应商外发放行 → 提取实体/事件/关系 → 校对 → 查看图表 → 导出。

P0 页面建议控制为：案件列表、材料目录、脱敏工作台、分析复核工作台、图谱与导出页、管理设置页。任务状态可作为全局抽屉，不新增独立门户体系。

本轮以 PDF 集中阅卷为首版输入，不额外建设非 PDF 上传入口、检察机关平台对接或自动获取案卷功能。

### 4.2 明确不做

- 当前本所试用不做外部律所入驻、自助支付、套餐营销和跨所管理后台；保留同所不同案件/团队的权限隔离与用量控制。原文中的多所测试要求仅在实际交付支持多个律所空间时启用，当前必测同所案件隔离。
- 不做律师 CRM、营销获客、全所财务、电子签章和通用 OA。
- 不做胜诉概率、自动判案、自动认定犯罪关系或证据真伪。
- 不将分析图表称作原始证据，也不承诺法院会采纳。
- 不承诺检察院或法院采纳任何辩护文书；不由模型自行编造或补充法条、司法解释、案例；不自动向任何机关提交、发送或签章。
- 不将内部研判报告中的待核查事项、内部评议和不利分析直接搬入对外文书。
- 不在未评估条件下处理涉密、明确禁止外发或来源权限不明的材料。
- 不把脱敏副本视作当然匿名化，不承诺“100% 无泄露”或“自动满足所有合规要求”。
- 不默认联网搜索、抓取外部资料、跨案训练或把案件内容用于平台产品优化。
- 不同时承诺所有格式、所有案由、双供应商和全套私有化首发。

## 5. 核心业务流程

1. **建立案件**：确定案件编号、成员、使用目的、处理限制及指定复核人员；云端案件标题不得直接携带未放行真实身份。
2. **本所导入与预检**：在本所受控环境批量选择已有 PDF，检查页数、密码、损坏与可读性，登记本次材料批次；此步不是上传原卷至 SaaS。
3. **本所解析与脱敏**：按页读取可用文字或进行本地 OCR，识别候选敏感内容，以同案代号替换；图片中的姓名、签名、印章等进入单独复核。
4. **人工复核**：逐项检查标注、遗漏、误标和上下文可识别性；明确精确日期/金额等需要保留的字段及原因。
5. **生成与放行**：先生成脱敏副本并复检，再针对确定版本、用途、接收方记录外发许可。
6. **提交分析**：展示待发内容类别、供应商、费用估算和材料范围；只有放行内容进入分析。
7. **结构化提取与复核**：将输出映射为实体、事件、关系和来源锚点；不合格输出进入待处理状态。
8. **图表及导出**：默认显示律师确认的结果；草稿另设明显标识，导出包含来源清单和审核状态。
9. **追加与更新**：新增材料单独走脱敏放行；生成差异结果，不覆盖既有确认内容。
9a. **文书起草（v0.2.2 建议）**：律师选择文书类型和所依据的已确认底稿，生成带引用草稿；逐段采纳、核验引用后，在本所端回填身份并签发对外提交版（见 FR-13）。
10. **归档与删除**：按适用政策处理文件、索引、任务副本和备份；保留必要的最小审计信息并提示例外。

### 5.1 检察院阶段 PDF 集中阅卷工作流

本节将用户确认的场景转换为首版功能建议与验收条件；不是对真实案卷已经完整取得、允许外发或程序阶段的法律判断。流程限于律师已经合法取得且获准处理的 PDF，不连接检察机关平台，也不自动获取案卷。

| 步骤 | 工作内容与用户看到的结果 | 处理位置/完成条件 |
| --- | --- | --- |
| 1. 建立阅卷批次 | 把本次获得的一组 PDF 归入案件，登记卷名/卷号、文件、页数和取得日期；展示导入成功、重复及失败清单 | 原卷和可能含身份的原文件名留在本所；取得日期由用户登记，不用文件修改时间冒充 |
| 2. 整理卷内目录 | 保留已有书签/目录；本地提出笔录、书证、鉴定文书等候选材料边界，律师可拆分/合并与校正 | 同一 PDF 可以包含多份材料，同一材料也可跨文件；候选目录不等于已确认的证据目录 |
| 3. 逐页解析与校对 | 可用文字页读取文字，扫描页本地 OCR，混合页检查缺失区域；低质量文字、缺页疑点、重复页和异常页面可见 | 不因部分页面有文字就跳过其他扫描页；表格、手写或难辨页面标记待核查，不擅自补写 |
| 4. 脱敏与复核 | 在本所对照原卷、候选敏感项和脱敏版；建立同案代号，检查姓名之外的签章、隐私、文件属性及上下文 | 未完成复核不得外发；本地处理不可用时暂停，不回退到外部原卷 OCR |
| 5. 选择分析范围并放行 | 显示准备发送的脱敏版本、页段/材料范围、用途及供应商；逐批放行，标明未纳入部分 | 确认放行才上传脱敏内容；记录处理范围，不能称为整个现实案卷已完整分析 |
| 6. 形成集中阅卷工作台 | 列出材料目录、时间轴、人员/物品关系、证据—事实关联、笔录对照及待核查事项；每项结果可回链 | 机器提取为候选，律师可修订；缺少起诉材料时按实际文书类型展示，不生成起诉指控 |
| 7. 中断与继续 | 保存最后阅读位置、笔记、已核对条目、待办和各处理阶段进度；再次打开继续 | 阅读过、脱敏复核通过、外发放行、模型处理完成和律师确认是不同状态，不互相自动替代 |
| 8. 追加与内部导出 | 补充 PDF 建立新批次，核对同案身份，生成新增/变化清单；导出阅卷摘要、图表、来源目录及待核查清单 | 只处理获批的新范围；保留原人工修订和历史快照，受变化影响的结论提示复核 |

**卷内定位与原卷保护**

- 本所原始 PDF 保持不变；材料拆分优先采用目录与页段标记，不为方便分析覆盖、重排或截断原卷。
- 来源锚点同时保留文件版本、PDF 物理页序、卷内印刷页码及页内位置；封面、目录、重复印刷页码、未编号页允许存在。无法识别印刷页码时明确为空，不能猜测补号。
- 材料跨页/跨文件或脱敏版重新分页时保留映射；改正目录边界、OCR 或页码后，只更新关联映射并提示受影响成果复核，不能把历史来源无提示指向新内容。
- SaaS 中的引用只指向已放行脱敏版本，使用脱敏标题和摘录；原卷回查及真实身份映射仅在本所受控端进行。原卷全文检索及其索引也留在本所，不将原文送到外部向量化或搜索服务。
- 本地阅卷笔记可能写回真实身份；上传前必须经过同等检查与放行。断点续阅位置可用无身份内容的标识表示，但不能夹带原文、截图或本地真实路径上报。

**材料覆盖与进度**

展示本次导入总页数，以及可读取/待校正、脱敏已复核/待复核、已放行/未放行、分析已覆盖/失败/排队的各阶段数量，注明各自分母。阶段可以重叠，不把不同阶段页数相加作为总数；律师已读进度与处理进度分别计算。

发布快照写明纳入的材料批次和脱敏版本、排除或失败范围、生成时间及审核状态。补充材料未处理完成前，不沿用“全部材料分析完成”标签；这里的“全部”仅指明确列出的输入集合。

**拟定页面组织**

仍沿用第 4 节的六个页面区域，不新增多套门户。集中阅卷主视图建议左侧卷/材料目录，中间 PDF 与对照视图，右侧笔记、相关事件及待办；上方切换时间轴、关系、事实关联和笔录对照。原文对照仅在本所受控端提供，云端页面只加载放行内容。具体界面在原型阶段验证。

## 6. P0 详细功能与验收

### FR-01 案件与材料管理

- 支持创建案件、邀请成员、分配案件角色、退出/移除成员、归档案件。
- 材料记录包括材料代号、证据编号、类型、来源说明、页数、版本、处理状态和上传者；真实文件名留在允许的环境。
- 支持批量导入、排序、重复文件提示、单文件失败重试；重复提示仅限同一律所且受案件权限约束。
- 同名不同内容视为不同版本或不同材料，必须由用户选择；不可按文件名直接覆盖。
- 文件指纹用于检测内容变化，不等于对真实性、形成时间或证据资格的认证。
- **验收**：混合导入正常、重复、加密、损坏和不支持格式后，逐文件显示明确状态，成功数量与材料目录一致；失败材料不被算作已分析。

### FR-02 解析、OCR 与完整性检查

- P0 输入为 PDF，设计覆盖可搜索、扫描及混合页；独立图片和其他文件格式导入后置。加密文件由用户在本所受控环境解锁后导入，不提供密码破解。
- 保留文档版本、物理页序、页内区域与 OCR 文字之间的对应关系；印刷页码与 PDF 页序分开显示。
- 检测空白、模糊、旋转、无法解析和文字识别不可靠的页面，提供人工校正入口。
- 原卷 OCR、页面预览和候选脱敏识别必须在 A3 确认的本所受控环境完成；没有本地处理能力时暂停，而不是自动切换外部 OCR。对原卷使用云 OCR 属于变更数据边界，不能仅凭供应商评估或一次按钮确认绕过。
- 对暂不支持的表格布局、手写和特殊字符明确提示，不擅自补全文字。
- 文件上限、单案页数、并发数按第 11 节候选负载压测后确认，超限必须提前显示。
- **验收**：任意 OCR 片段可定位到原页；失败页有可见标识；修正 OCR 后相关脱敏及分析版本进入需复核状态。

### FR-03 敏感信息识别与脱敏策略

| 内容类别 | 建议默认处理 | 特别说明 |
| --- | --- | --- |
| 人名、组织名、统一社会信用代码 | 使用同案稳定代号或遮除 | 组织信息也可能涉及保密；不得仅识别自然人信息 |
| 身份证件、电话、邮箱、银行卡/账户 | 遮除或代号化 | 资金分析保留“账户 A/B”关系，不默认保留尾号 |
| 精确住址、定位、案号、合同号 | 按用途替换或泛化 | 可与公开信息关联识别，不能简单列为低风险 |
| 签名、印章、脸部、二维码/条码 | 区域遮除并人工复核 | 不因正文已脱敏就跳过图像信息 |
| 健康、未成年人、家庭隐私等内容 | 高风险提示及最小必要处理 | 是否允许进入云端需按案件目的判断 |
| 商业秘密、业务数据、律师工作备注 | 用户规则与人工标注结合 | 不宣称自动识别全部秘密或工作成果 |
| 日期、金额、地点、职业等组合信息 | 默认提示上下文识别风险，由复核人决定必要保留范围 | 精确分析和不可识别性存在取舍 |

- P0 只提供本所内部研判使用的脱敏分析版，并对模型外发另行逐版本放行；对外交流模板后置。内部使用不替代外发复核，也不自动代表达到匿名化。
- 同一个人跨文件使用稳定案件代号；别名候选需人工确认。存在同名、OCR 错字和多人共用账户时不能只按名字合并。
- 支持单处标注、同案匹配预览、逐处/批量确认、误标撤销、手工框选和规则例外理由。
- 先本地规则/识别，再人工复核；不能为了“先脱敏”把未脱敏文本发给外部大模型。
- **验收**：同一身份经确认后在同案输出一致；不同案件不共用映射；有疑义的同名对象保留为两个对象并进入核对队列。

### FR-04 脱敏工作台与复检

- 本所受控端提供原卷与脱敏版对照：原文预览、候选敏感项、案件代号及脱敏预览；SaaS 仅展示允许进入云端的脱敏版本。界面一体化不得以原卷上传作为实现前提。
- 待复核项按页面与类型组织；没有自动检测到敏感项的页面也必须纳入页面完整性确认。
- PDF 不只叠加黑色矩形：发布副本不得残留被遮内容的文字层、批注、附件、表单字段或历史修订信息。
- 清理文件名、作者属性、缩略图、隐藏文本、图片附带信息等非正文位置；检查导出和模型请求中的引用标题。
- 已放行副本变动后必须新建版本；原放行记录仅对旧版本有效。
- 显示残余风险，而非用“脱敏安全分 100”代替审核。
- **验收**：受控测试样例中，选择/复制文字、检索及独立解析脱敏副本均不能恢复已遮内容；抽查图像区域和元数据一致；未完成复核时无法生成有效外发许可。

### FR-05 外发放行与请求边界

- 放行记录绑定材料版本、用途、接收方/供应商、处理范围、审批人、审批时间及状态；是否需要到期时间由律所策略决定。
- 分析请求只包含最小必要的已放行脱敏文本或已放行图像、案件代号和来源标识；不包含身份映射表。
- 用户输入的分析备注、搜索问题、图谱标签和文件标题也属于可能的外发内容，必须执行同样检查。
- 发送前核验当前权限、批准版本及供应商；不能只在页面按钮上拦截。
- 供应商切换、用途变化或新版本出现时需要重新匹配放行范围，不自动沿用旧许可。
- 复核撤销或发现泄露后：停止尚未发送的请求，隔离相关成果，列出已发送记录并进入处置流程；不能承诺撤回模型已经收到的数据。
- **验收**：对未放行、版本不一致、供应商不一致或权限已撤销的任务，模型外发次数为零，且留下不含正文的审计记录。

### FR-06 结构化案情提取

- 提取实体、事件、关系与材料摘要；以结构化底稿为准，不让模型直接决定最终图片布局或执行输出中的代码。
- 每项输出携带材料版本、页码/区域及最小必要的脱敏原文摘录；引用必须能在指定版本中核验。
- 区分“材料记载”“当事人主张”“人工备注”“分析推测”；正式事实图默认不显示分析推测。
- 无来源的模型结论进入待核验队列，禁止当成确认事实发布；人工补录可保留，但必须标明来源缺失及录入者。
- 不用模型自行给出的百分比充当可信概率；建议展示证据完整性、冲突状态和复核状态。
- 长案卷分段处理时显示已处理、失败、待处理页数及覆盖清单；合并同一事件时保留全部来源和人工决定。
- 模型新增事件或关系先进入差异清单；人工修改优先保留，冲突由用户选择接受或拒绝。
- **验收**：无法解析的结构、非法字段、无效实体引用、伪造页码、空输出、输出截断都不能直接落入正式图谱；提供可恢复状态。

### FR-07 时间轴

- 事件字段至少包含：事件编号、简述、时间原文、时间精度、可选起止时间、事件类型、参与实体、来源集合、争议状态、复核状态。
- 区分发生日期、材料形成日期和材料提交日期；原文未给出发生时间时不拿文书日期冒充。
- 支持精确日期、月份/年份、区间、相对表述和未知时间；推导时间须写明依据并待确认。
- “2024 年春”“约三个月后”等不得不加说明地转换成某一日；未知时间进入独立列表。
- 视图可按参与人、事件类别、材料来源和复核状态过滤；支持手动新增/修改、合并/拆分事件及保留理由。
- 两份材料日期冲突时并列展示来源，不按模型偏好选一个。
- **验收**：精确、区间、未知及冲突时间都能正常展示和导出；用户点击事件可回到正确脱敏材料版本。

### FR-08 人物与组织关系图

- P0 节点以自然人和组织为主；根据选定案由允许合同/账户作为关联节点，不扩展成通用知识图谱平台。
- 关系包含方向、类型、时间范围、来源及状态；例如“受雇于”“签约相对方”“向某方付款”等需有材料支持。
- “犯罪嫌疑人/被告人/被害人/证人/辩护人”等是需按材料与阶段记录的案件身份；“账户登记人/实际使用人/雇员”等属于另有依据和时间范围的关系，不能相互混用，也不能由联系网络自动确定主从犯。
- 共同出现在同一页不等于存在社会关系；两条关系也不自动构成第三条推断关系。
- 支持同名实体人工合并/拆分、搜索、聚焦邻接对象、类型过滤、节点拖动、布局保存。
- 大图分组或聚焦展示；若截取局部，导出明确标注过滤条件及未展示数量。
- **验收**：不存在指向已删除节点的悬空关系；全部正式关系均可回链；同名不同人的合并可以撤销并恢复来源归属。

### FR-09 证据目录与复核工作台

- 基于材料目录形成证据编号、名称、页码范围和简要内容；证明目的由律师填写或确认。
- 从时间轴事件/关系进入来源，也能从材料查看被哪些事件/关系引用。
- 待办分类：脱敏复核、OCR 校正、同名合并疑义、无效引用、时间冲突、模型差异。
- 支持成员指派、状态记录、评论与修改理由；评论同样执行案件权限与外发检查。
- **验收**：修改证据编号不丢失底层引用；一个事件被多份材料支持时可逐份查看，不遗漏反向来源。

### FR-10 内部研判报告、导出与版本快照

**格式与首版优先级**

| 输出 | 首版范围 | 使用方式与限制 |
| --- | --- | --- |
| PDF 研判报告 | P0，默认传阅版 | 可搜索文字、目录/书签、页码、清晰图表和来源附录；用于内部会议、阅读及打印；不声称 PDF 不可修改 |
| Word 研判报告（DOCX） | P0，可编辑讨论版 | 标题、正文、表格及待办为可编辑内容；图谱作为清晰图片并附节点/关系或事件明细，首版不承诺在 Word 内编辑图节点 |
| HTML 交互版 | 可选 P1 | 需要缩放、筛选和点击时再提供；不能替代 PDF/DOCX，默认不发布互联网公开链接 |
| PNG、CSV | P0 辅助输出 | 单张图和结构化明细另存，不替代完整研判报告；CSV 保留文本安全处理 |
| PPT、SVG、复杂模板设计器 | 后续候选 | 不因增加 Word 输出同步扩张全部格式与模板体系 |

**建议报告目录：一份报告，前简后详**

1. 封面与范围：案件代号、材料批次、文书范围、报告编号/版本、编制/复核人、生成时间及审核状态。
2. 会议摘要：主要研判问题、已核对材料要点、尚待确认事项及本次希望讨论的议题；建议控制在前 1—2 页，篇幅不是硬性删减依据。
3. 案情时间轴与人物/物品关系：每张图有图例、来源编号、显示范围和必要的配套明细表。
4. 证据—待证事实关联与笔录对照：支持和反驳材料并列，保留陈述背景、分歧与审核状态。
5. 律师确认的争点及所选案件专题：仅使用有材料支撑的内容；不为填满模板虚构检方指控、鉴定意见或法律结论。
6. 待核查清单与会议讨论事项：区分当前未取得的材料、未处理页、未确认陈述和需由律师评议的问题；留负责人/处理状态字段，不自动给出法律期限。
7. 来源附录：条目编号、材料代号、卷号/材料名、材料版本、PDF 物理页序、卷内页码及必要的已放行摘录。

章节随所选内容生成；没有资料的专题注明未纳入原因，不用空白图或编造内容占位。会议摘要的事实表述同样需要来源；摘要不能丢掉关键反向材料或不确定性。

**PDF/DOCX 版面与回链**

- 两种格式来自同一发布快照，事实条目、金额、来源编号、过滤范围与状态一致；分页不要求完全相同。页脚区分报告页码与来源材料页码。
- 建议默认 A4 纵向正文，宽表/图可用横向页或拆成概览与局部详图；不得为塞入一页而缩成无法阅读的小字。中文表格跨页重复表头，重要图表配说明与必要的文字表。
- PDF 中目录和来源编号跳转到报告内对应章节/附录；没有一同携带源材料时，不伪装支持离线打开原卷。附录应足够让有权人员在本所系统定位来源，导出报告不默认附带整套案卷。
- DOCX 提供正常段落、标题层级、表格和可更新目录，不将全文做成截图；绘图底稿的编辑仍在系统内完成。参考 Word/WPS 的具体版本需在发布前验证，不宣称所有版本完全一致。

**审核、流转与安全**

- 正式报告仅将律师确认的条目作为确认内容；待核查问题可以放入单独章节并明确状态，不让讨论清单冒充既定事实。允许明确选择的讨论草稿，整份标注“未复核”，关键条目保留局部状态。
- 导出前预览纳入范围、权限与敏感项，记录报告版本及导出人。报告中默认案件代号，不包含身份映射；真实身份内部版仍需本所受控端的另行授权和处理，当前不自动启用。
- Word 手工修改属于派生讨论稿，不自动同步系统、不自动沿用原报告复核结论；重新导入和自动合并 Word 修改不进入首版。再次发布需由负责人核对版本与状态，不能承诺阻止文件被手动修改。
- 发放版应从受控底稿生成干净副本，检查 DOCX 批注、修订残留、文档属性、隐藏内容、嵌入附件及 PDF 元数据，不将隐藏原文或身份信息随报告带出。草稿如需含批注，必须明确选择并单独审查。
- 如实现离线 HTML，仅包含明确选中的放行内容；不在隐藏 DOM、脚本数据或附件中打包未显示的原文，不调用外部字体/CDN、遥测或联网分析。在线受控查看与离线文件另行区分。
- “仅供本所内部研判”等标识、水印和授权下载用于提醒与追溯，不代替文件接收人的权限管理，也不承诺收回已下载的 PDF/DOCX/HTML。
- **验收**：PDF/DOCX 内容与快照一致、中文和大图可读、表头及引用编号完整；Word 正文/表格可编辑；来源定位明确；输出不包含身份映射、隐藏未放行内容或不可用却伪装可用的原卷链接。

### FR-11 案件隔离、审计与生命周期

- 所有文件、正文、缩略图、搜索/分析结果、任务状态、导出、缓存和索引都受律所及案件权限约束。
- 平台人员无默认正文访问权；支持客户授权、限时、最小范围的故障处理，并记录访问。
- 审计包含操作人、律所/案件标识、动作、时间、对象版本、目的及结果；普通日志不保存原文、映射、完整模型请求或 API 密钥。
- 审计不可由普通成员任意修改；审计完整性、保存期限和查阅权限另行确认。
- 删除包含派生文本、图片副本、索引、报告和任务临时数据；备份按声明周期淘汰，恢复时重新应用删除记录。
- 遇到依法或依约必须留存的事项，阻止直接删除并说明依据与责任人；不擅自规定统一保留天数。
- **验收**：本所无权限案件/团队之间，列表、预览、引用、下载、搜索和后台任务都不返回对方内容；若未来实际支持多个律所空间，再追加跨所隔离测试。删除后活动存储不可读取，备份残余及期限可说明。

### FR-12 任务、供应商与费用控制

- 显示排队、解析、待复核、可分析、分析中、部分失败、待校对、完成等阶段及覆盖页数。
- 支持取消未开始工作、失败部分重试；取消后已发生的外部费用不承诺退款。
- 每任务记录供应商、模型标识、模板版本、输入材料版本、用量与费用估算；实际费用以适用账单校核。
- 限额、并发限制及重试次数由获批策略控制；达到预算上限暂停，不无限重试。
- 供应商故障时保留任务进度，不静默切换到未经放行的备用模型。
- 本所首版提供成员开通/停用、用量台账与内部配额，不建设外部律所开户、销售套餐、自助支付或自动开票。
- **验收**：重复点击不会创建重复分析账单；部分失败重跑不重复插入事件；预算拦截、暂停和审计一致。

### FR-13 辩护文书辅助（v0.2.3 已确认首版范围）

- **首版文书类型（固定三类）**：质证意见（逐项列明证据名称、卷页、真实性、合法性、关联性、证明目的及意见）；审查起诉阶段法律意见书（不起诉、罪轻、量刑方向）；羁押必要性审查申请。取保候审申请、调取证据申请、非法证据排除申请等后置。
- **参考样本**：本所暂无模板。提供文本输入框（粘贴样本正文或写作要求）和文件上传入口（PDF/DOCX/TXT），按文书类型归类；保存前律师必须勾选“确认已脱敏”，未勾选不保存。样本只存本所端，可查看列表和删除；生成时只取同类型样本作为结构与文风参考，不作为事实或引用来源。
- **输入限定**：只使用律师已确认的底稿条目（C1 证据—待证事实、C2 陈述对照、C3 要件—争点树、C9 取证流转、C10 程序泳道、C11 数额口径、C12 定罪与量刑面板等）；未确认、草稿或待核查条目不得作为论据，除非律师逐条选入并确认。
- **输出形态**：生成分段初稿；每段附卷/页引用，并列出律师已标注的不利或相反材料，提示需回应之处，不得静默省略。
- **修改意见与重生成**：律师可对任一段落填写修改意见，模型仅重生成该段，保留各版本及对应意见；重生成后该段回到“待确认”，不得继承原确认状态。
- **引用核验**：模型给出的法条、司法解释、案例一律标为“待核”，由律师核对现行有效文本后改为“已核”；首版不默认联网检索。卷页引用必须能解析到已放行材料的来源锚点，无法解析的引用进入隔离区，不进入正文。
- **逐段确认**：每段有“待确认/已确认/驳回”状态，律师可直接手改或提修改意见重生成，最终必须由律师逐段确认；记录操作人、时间、所依据底稿版本和段落版本，形成采纳记录；底稿后续变更时提示受影响段落，不自动改写已确认内容。
- **身份回填**：发送给模型的请求只含同案代号；真实姓名等身份信息只在本所受控端按映射回填到文书，回填过程和结果不上传、不进入模型请求或普通日志。
- **对外提交版**：与内部研判报告分开存储和标识。导出可编辑 DOCX（可另出 PDF）前必须满足：全部段落已采纳、无“待核”引用、无内部评议/待核查/内部水印残留、无批注修订和隐藏内容；之后由律师签发并记录签发版本。系统不自动提交、发送或签章。
- **验收**：见 AT-29 至 AT-38。

## 7. 数据边界与领域关系

### 7.1 已确认处理边界（A3）

```text
律所受控环境
  原始材料 → OCR/解析 → 敏感内容识别 → 人工复核
  身份映射单独保管           ↓
                        脱敏副本 + 外发放行
                               ↓
SaaS 案件空间：脱敏材料 / 代号 / 来源锚点 / 权限 / 任务
                               ↓ 最小必要的放行内容
指定模型服务：结构化草稿 → 回到 SaaS 校验与律师复核
                               ↓
                       时间轴 / 关系图 / 导出快照
```

“律所受控环境”不自动等于完全安全，仍需明确设备、访问与临时文件策略。SaaS 和模型方收到的脱敏副本也按受保护案件资料管理；仅更换姓名不会取消保密要求。

| 数据类型 | 已确认边界内的允许位置 | 默认禁止的用途/流向 |
| --- | --- | --- |
| 原始材料、未脱敏 OCR、身份映射 | 律所受控环境 | SaaS 正文日志、外部模型、第三方遥测 |
| 放行脱敏副本 | 案件授权环境和获批服务 | 跨案复用、平台训练集、未经批准的供应商 |
| 事件、关系、模型摘要 | 所属案件空间 | 无权限客户、公开搜索索引 |
| 最小操作与用量记录 | 受控审计/计费环境 | 拼入原文或身份映射 |
| 本地真实身份版成果 | 有权成员指定位置 | 自动同步云端或混入普通导出 |

### 7.2 最小领域关系

- 一个律所空间有多个案件；案件拥有自己的成员授权和材料。
- 一份材料有多个版本；一个脱敏版本对应确定原始材料版本、脱敏规则及复核记录。
- 一个放行记录限定版本、用途和接收方；一个分析任务仅引用匹配的放行输入。
- 一个来源锚点绑定材料版本及具体位置；同一事件/关系可有多个锚点。
- 一个实体可有多个经确认的别名；身份映射与云端实体代号并非同一份资料。
- 关系连接两个实体并携带依据；事件可涉及多个实体。
- 一次分析产生一组候选项；人工确认记录独立保留；发布快照固定当时成果。

### 7.3 状态规则

| 对象 | 主状态 | 关键限制 |
| --- | --- | --- |
| 材料 | 导入中 → 待解析 → 待脱敏 → 待复核 → 已生成脱敏版 | 失败和不支持状态必须可见 |
| 脱敏版本 | 待复检 → 可申请放行 → 已放行 / 驳回 / 撤销 | 内容变更新建版本，不改旧版 |
| 分析任务 | 待发送 → 运行中 → 待校验 → 待律师复核 → 完成 | 可部分失败、取消、暂停；不得把部分成功显示为全卷完成 |
| 事件/关系 | 机器候选 → 待核验 → 律师确认 / 驳回 | 来源状态和争议状态独立于审核状态 |
| 成果快照 | 草稿 → 已发布 → 标记失效 | 来源撤销或发现泄露时标记受影响成果 |

- P0 先选一个通过验收的供应商；另一个使用同一合法测试集比较。模型上下文、文件处理能力、价格与并发额度均在选型时重新确认，不在本稿虚构数值。
- 记录模型标识和提示模板版本；结果快照可复核，但不承诺随机模型每次输出完全一致。
- 默认关闭外部搜索和无关工具；文档内容是待分析数据，不能改变系统权限、外发目的地或审批规则。

- 敏感内容出入检查同样覆盖模型结果：模型不得凭上下文猜测真实身份并自动写回。

本轮取得的 Kimi 开放平台服务协议标示生效日期为 2026-08-31：第五部分包含客户数据处理约定，第六部分第 3 项同时涉及输入、输出与反馈用于模型服务优化。[S7] 本产品的准入要求是：由供应商书面澄清这些条款对拟购 API 方案的适用范围，以及留存、训练/优化、分包和删除安排；在澄清并批准前，不使用真实客户案卷开展试运行。此项并不推定所有 Kimi 企业方案具有相同条款。

### 8.3 质量防线

1. 输入完整性：页数、OCR 失败和材料覆盖范围可见。
2. 输出结构：类型、必填字段、实体引用和日期范围校验。
3. 来源可核验：锚点存在、摘录可匹配；存在来源不代表结论必然正确。
4. 人工复核：重点校对实体合并、关系类型、时间及金额；正式成果有负责人。
5. 增量更新：模型建议与人工版本分别保留，不能覆盖已确认修改。
6. 质量反馈：用户可标记错误类型，保存最小必要记录；客户原文不自动进入平台训练或公共评测集。

- 文件安全：导入前做格式与内容预检；解析环境限制权限，不执行附件主动内容；仅在允许的受控环境中处理原卷。
- 运维边界：错误报告、遥测、客服截图和测试样例均不得顺带上传原文或映射；生产数据不能复制到开发环境。
- 导出安全：CSV 文本字段按数据而非可执行公式处理；模板与图表标签不得成为脚本执行入口；不通过外部绘图网站渲染敏感底稿。
- 事件处置：具备停发、隔离、追踪受影响版本、通知负责人和依要求报告的流程；演练覆盖错误外发及成员撤权。
- 用户权利与投诉：提供可找到的联系入口，按核实的身份及案件限制处理查阅、更正、删除等请求；不能把无权请求者引导到案卷正文。
- 合规标识：对依法须保留的生成标识与无关个人信息元数据分类处理；清理与标识需求冲突时暂停发布并升级处理，不默认全删。

## 10. 非功能要求与产品可用性

本节为候选要求，需与首批客户、部署条件和预算共同确认；不是已测性能或销售 SLA。

| 维度 | 需求与检验方式 |
| --- | --- |
| 易用性 | 桌面端浏览器优先；首次使用者在指导材料下独立完成一次脱敏—分析—导出；测试记录阻塞步骤 |
| 可理解性 | 不仅用颜色区分状态；明确显示“待核验”“有争议”“律师确认”和处理覆盖范围 |
| 图表可读性 | 中文、长标签、密集图表均可缩放/筛选；导出前预览分页效果，不用无限缩小字体掩盖超量 |
| 稳定性 | 任务异常不丢失已确认编辑；允许安全重试，状态不会永久卡在运行中 |
| 并发编辑 | 检测过期版本修改，避免后提交者无提示覆盖前一人的工作 |
| 可观测性 | 用匿名任务标识定位故障；记录阶段耗时、失败类别、用量，不靠收集案卷正文排查 |
| 兼容性 | 明确列出已测浏览器、受控端运行环境和支持格式；浏览器不能完成的本地能力提前说明 |
| 备份恢复 | 在确认恢复时间/恢复点目标后演练；验证权限、版本及删除记录恢复一致；目标未定前不售卖高可用承诺 |
| 可退出性 | 授权成员可导出脱敏材料、事件/关系底稿、目录及来源清单；停用时说明数据保留、导出与删除流程 |

## 11. 评测与上线验收

### 11.1 评测集与测量方法

建议先准备 **不少于 20 组合法合成或经批准的测试案卷、合计不少于 1,000 页**，覆盖印刷体、扫描、同名不同人、别名、签章、表格、模糊日期、相互矛盾记载、文件元数据和长案卷。数量为待确认的试点设计，不代表统计充分性。

由两名具备案情理解能力的标注者独立标注敏感区域、实体、事件、关系和来源，分歧经复核解决；调试样本与最终验收样本分离。所有指标按材料类型、风险类别和案卷分别报告，不能只给总体均值。

| 指标 | 定义 | 候选目标 / 决策规则 |
| --- | --- | --- |
| 敏感项识别召回 | 被正确识别的敏感出现位置 / 人工标注敏感出现位置 | 分类别测量并提出阈值；没有标注数据前不宣传识别率 |
| 误遮比例 | 被错误处理的非敏感位置 / 全部处理位置 | 和召回、人工修复时间一起看，不通过遮掉整页刷召回 |
| 发布残留 | 放行测试副本中仍暴露的应处理敏感项 | 测试集发现任一高风险残留即阻止发布；测试未发现不等于现实零风险 |
| 来源有效率 | 可定位且摘录匹配的正式条目 / 正式条目 | 发布检查要求 100%；不能替代语义正确性检查 |
| 事件/关系准确与覆盖 | 与人工底稿比对正确性与遗漏 | 分别记录精确率、召回及关键错误；试点评审后确定阈值 |
| 人工改写保护 | 追加分析后正确保留的人工确认项 / 应保留项 | 回归测试 100%；丢失任一已确认修改即失败 |
| 外发授权匹配 | 有有效版本、用途与接收方许可的请求 / 所有请求 | 受控测试 100%；不匹配请求不得发送 |
| 隔离 | 无权主体可获得的他案/他所数据条数 | 受控测试为 0；任何泄露阻断上线 |
| 完成效率 | 人工基准耗时 vs 含审核/纠错的工具辅助总耗时 | 建议以中位耗时降低 30% 为试点假设，同时报告样本数、长尾与质量；不是既有效果 |
| 单案成本 | 解析/OCR、模型、存储导出和支持成本总和 | 先实测后定价，不用模型单次调用费冒充全部成本 |

模型质量阈值尚未得到客户确认，属于真实客户试点前必须关闭的待办。不得把“已经记录待确认”当作已通过验收。

### 11.2 候选负载基线

- 为便于初次压测，建议使用：单案 50 个文件/500 页、单文件 50 MB、5 个并发分析任务，以及单图 200 个节点/400 条关系。均是测试设计候选，不是用户实际规模或产品承诺上限。
- 同时测试一个经批准的大卷超限场景，验证提前提示、分批和覆盖清单，而不是静默截断。
- 记录设备配置、扫描质量、网络和供应商额度，分别测上传、OCR、脱敏生成、模型分析及导出耗时。
- 律师人工复核时间单列；端到端完成时间包含复核，不用服务器耗时替代用户工时。
- 交互候选目标：普通列表/保存操作 P95 不超过 2 秒，任务接收确认不超过 3 秒；在最终确认负载下测量，外部分析时长显示实测范围，不预先承诺秒级全卷出图。

### 11.3 必测业务场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AT-01 | 同一人在合同、聊天截图和转账凭证中出现 | 经确认映射一致；上下文及图像残留复检通过 |
| AT-02 | 同名的两个人参与同一案件 | 不自动合并；手动拆分后引用及关系归属正确 |
| AT-03 | 姓名在正文、文件名、批注和图片中同时出现 | 发布副本与请求不残留应遮内容；依法需保留的标识仍有效 |
| AT-04 | 一份 PDF 只有可见遮盖但文字层仍有姓名 | 复检失败，禁止放行；不以肉眼黑块判定成功 |
| AT-05 | 两份材料对付款日期说法不同 | 保留两个来源与争议标识，不擅自择一 |
| AT-06 | 仅出现“大约三个月后”，没有明确基准日 | 不伪造精确日期；保留原文及未知/模糊状态 |
| AT-07 | 模型生成未出现的人物、关系或不存在的页码 | 无效候选被隔离，正式图谱及导出中不可出现 |
| AT-08 | 材料含意图改变分析规则的指令文字 | 只视为材料内容，不改变权限、审批或数据去向 |
| AT-09 | 律师已修正金额，随后追加新材料重新分析 | 原确认值保留；冲突作为差异呈现，不被覆盖 |
| AT-10 | 一名成员在任务排队期间被撤权 | 不可查看或下载；由权限失效触发的待发任务重新校验 |
| AT-11 | 供应商异常、输出为空、任务中断 | 显示实际失败阶段；安全重试不重复记账或插入条目 |
| AT-12 | 案卷部分页面 OCR 失败或超上下文范围 | 明示未覆盖部分；不能显示“全卷分析完成” |
| AT-13 | 删除案件后进行一次备份恢复演练 | 删除策略继续有效；受限制内容不会重新开放 |
| AT-14 | 大图、长标签与跨页时间轴导出 | 内容不裁切；分页/过滤及来源索引明确 |
| AT-15 | 本所不同案件授权成员分别搜索、预览、引用及下载 | 无他案资料泄露；未来交付多律所空间时另加跨所测试 |
| AT-16 | 用户在分析备注写入未放行真实身份 | 阻止外发并引导回到受控脱敏流程，不只检查附件 |
| AT-17 | 同一 PDF 含可搜索文字页、纯扫描页和混合页 | 逐页完整检查；扫描文字本地识别；失效页可见且不被计入已覆盖分析 |
| AT-18 | 一个 PDF 内有多份笔录，某份材料又跨两个 PDF | 人工确认材料边界后，原卷不变；跨文件来源和页码仍可回查 |
| AT-19 | PDF 含封面、目录、无编号页和重复卷内页码 | PDF 物理页与卷内页码分别保存；事件点击回到正确版本/区域，不猜补页码 |
| AT-20 | 本地 OCR 不可用，或任务在放行前遇到异常 | 不向外部 OCR/模型发送原卷、OCR 原文或身份映射；临时文件和错误日志不越界 |
| AT-21 | 阅卷中断后继续，律师已读但未完成脱敏复核 | 阅读位置及笔记恢复；已读不等于已复核/放行，未放行材料不外发 |
| AT-22 | 首次分析后追加补充 PDF，与已有陈述有分歧 | 新批次独立复核放行，差异可见；人工确认保留，受影响条目提示复核，旧快照不改写 |
| AT-23 | 云端图表回链和处理日志引用含身份的原文件名/笔记 | 云端仅显示获批脱敏标题、摘录与来源；原文、真实路径和身份映射仅在本所侧可用 |
| AT-24 | 从同一发布快照分别导出 PDF 与 DOCX | 核心事实、金额、图例、来源编号、过滤范围及审核状态一致；仅允许正常分页差异 |
| AT-25 | 长篇中文笔录对照、宽图、多页来源表和混合横纵版面 | 无裁切、遮挡或过小文字；PDF 可搜索并可从目录跳转；Word 正文/表格可编辑 |
| AT-26 | 报告脱离案卷文件离线传阅 | 来源编号可到报告内附录，卷/页信息可查；不出现伪装为可访问原卷的失效链接，不默认嵌入整卷 |
| AT-27 | Word 讨论稿出现新增批注、修订或真实姓名，随后准备发放版 | 生成干净副本并重新检查内容与状态；不复用旧审核结论，不携带未放行隐藏信息 |
| AT-28 | 导出一份含待讨论事项的研判报告 | 确认条目与待核查清单状态分明；摘要不将待讨论推论提升为事实 |
| AT-29 | 草稿含模型给出但未核验的法条或案例，尝试导出对外提交版 | 导出被阻止并列出“待核”引用；律师核验改为“已核”后才可导出 |
| AT-30 | 文书仍有未采纳段落，尝试签发 | 不能生成提交版；可导出带“草稿”标识的讨论稿 |
| AT-31 | 对外提交版需回填真实姓名 | 模型请求、云端存储与普通日志中均无真实姓名；回填只发生在本所受控端，结果可审计 |
| AT-32 | 文书正文混入内部研判报告的待核查事项、内部评议或“仅供内部研判”标识 | 干净副本检查检出并阻止签发，指出位置 |
| AT-33 | 模型输出不存在的卷页、虚构证据名称或虚构案例 | 无法解析到来源锚点的引用进入隔离区，不进入正文，并提示律师 |
| AT-34 | 底稿中已标注的不利材料与某论点相关 | 草稿在该论点处列出不利材料并提示回应，不静默省略 |
| AT-35 | 已采纳段落所依据的底稿条目被修改 | 段落标记“依据已变更”，需律师重新确认；不自动改写已采纳文本 |
| AT-36 | 上传或粘贴参考样本时未勾选“确认已脱敏” | 拒绝保存并提示；样本不进入任何模型请求 |
| AT-37 | 已确认段落经律师提修改意见后重生成 | 新版本状态为“待确认”，保留旧版本与修改意见；未全部确认前不能签发 |
| AT-38 | 生成质证意见时存在法律意见书类型样本 | 只取质证意见类样本作参考；样本内容不作为卷页引用或事实来源 |

### 11.4 发布闸门

正式接触真实案卷前：处理依据、部署边界、供应商条款、客户协议及测试数据授权确认完成。对外商业上线前：P0 全链路、隔离/脱敏/回链回归、恢复演练、支持与事件处置流程通过，相关法定手续和标识评审完成。

以下任何一项未解决都不得以“有风险提示”为由放行：已知原文残留、越权获取案件、身份映射外发、无授权供应商转发、正式结论无有效来源却未标记、已确认修改被覆盖。

## 12. 推进顺序与内部价值验证

不先承诺开发周数；工期取决于原卷处理环境、文档类型和团队资源。以下阶段按验收推进：

| 阶段 | 产出 | 验证点 |
| --- | --- | --- |
| M0 需求确认 | 本所、广泛刑事业务、PDF、检察院阶段集中阅卷与原卷本所处理已确认；再核验样例、规模及本地运行条件 | 能按第 5.1 节走完一次现有 PDF 的阅卷流程；未确认参数显式保留 |
| M1 能力验证 | 用合成/获批样例走通脱敏、JSON 提取、回链和出图；检查数据路径 | 全流程看见输入、残留、耗时、成本和人工纠错量 |
| M2 MVP | P0 页面、单一模型接入、权限、快照和导出 | 第 11 节测试及约定质量阈值通过 |
| M3 受控试点 | 本所少量授权成员使用获批案件材料，记录整理与研判问题 | 阅卷工时、遗漏、关键错误及纠错负担形成证据 |
| M4 扩展 | 根据反馈增加冲突对照、争点矩阵、资金流或引用问答 | 每项功能有真实重复需求，不一次铺开全部 P1 |
| M5 辩护文书辅助 | 质证意见、审查起诉阶段法律意见书、羁押必要性审查申请三类；参考样本入口；基于已确认底稿生成带引用分段初稿，支持修改意见重生成、逐段确认、引用核验、本所端回填与签发 | 用合成或获批案例对比起草工时、引用错误和律师修改量；AT-29 至 AT-38 通过 |

本轮不验证外部售价或获客，先衡量本所集中阅卷、交叉核对及内部讨论的总工时和质量。保留模型用量、本地处理资源和内部费用核算；不建设外部销售计费系统。本所侧处理能力是已确认边界的必要条件，但桌面组件、本所服务器及浏览器本地方案仍未选定。

## 13. 关键风险与取舍

| 风险 | 影响 | 应对或待决定事项 |
| --- | --- | --- |
| 用可逆代号替代真正匿名化，却宣称无需保密 | 合规与客户信任风险 | 采用词汇表；残余风险与用途审批保留 |
| 本所处理增加安装、协作和支持负担 | 影响本所落地与使用体验 | 原卷边界已定；核验实际设备和工作方式后选一种本地实现，不同时建设三种形态 |
| 脱敏过度使日期/金额失真 | 图表失去办案价值 | 按用途保留必要事实，必要时缩小外发内容或不外发 |
| 高准确率均值掩盖个别敏感遗漏 | 案件泄露 | 分类型/案卷报告，保留人工审核，建立发布阻断标准 |
| 图谱美观但没有依据 | 错误传播与过度信赖 | 来源锚点、争议状态、律师确认、发布快照 |
| 首版目标过大 | 迟迟不能交付闭环 | 通用研判闭环、有限格式、单一模型优先；六类案件验证共用能力，专题高级功能分期 |
| 供应商默认条款不适合案件资料 | 真实试点无法启动 | 先书面核验，不靠产品水印、密钥归属或自带 API Key 绕过 |
| 图表进入庭审/对外传播 | 证据与展示混淆、额外治理要求 | 明示辅助整理属性，客户律师审核具体用途；必要时另立场景版本 |
| 模型虚构法条、案例或卷页 | 对外文书出错，损害当事人利益与律师信誉 | 引用一律“待核”，卷页必须可解析，未核验阻止签发 |
| 律师过度依赖草稿 | 论证质量下降、遗漏辩点 | 逐段采纳记录；草稿明确标识为辅助；不提供“一键成稿直接提交” |
| 内部研判内容流入对外文书 | 暴露辩护策略或不利分析 | 文书与内部报告分开存储；干净副本检查拦截内部标识和评议 |
| 不利材料被忽略 | 意见缺乏针对性、被检察院直接反驳 | 论点处强制列出已标注的相反材料并提示回应 |

### 第一轮：用户已确认

- Q1 使用者：本所，不是先卖给外部律所。
- Q2 材料范围：刑事案件案卷；后续已明确六类常见案件及广泛刑事业务，并确认 PDF 与检察院阶段集中阅卷。
- Q3 首要用途：内部研判，不是客户展示或庭审提交。

### 后续补充：案件类型已确认

- 用户列举诈骗、非法经营、强奸、猥亵、故意伤害、盗窃，并明确基本各类刑事案件均办理。

- 产品建议转为共用研判能力和可组合专题，具体开发清单仍需确认。

### 本轮：处理边界、格式与阶段已确认

- Q1 用户回复“按照建议来”：原卷、未脱敏 OCR 和身份映射留在本所受控环境，外发只针对复核批准的脱敏内容；数据边界 ADR-0001 改为 accepted，具体实现与供应商准入未确定。
